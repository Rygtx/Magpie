# 0.6.7 Beta 4 参数面板输入验收

实时参数面板分为关闭、编辑和预览。工具栏不获取游戏焦点；打开参数面板进入编辑，鼠标脱离 Magpie 的游戏捕获和坐标映射。单击游戏区域时，本次按下和松开全部由参数层接收，随后返回游戏并保持只读预览。标题栏、下拉选项列表和已开始的拖动均属于参数交互区域；移出面板不会退出编辑。

工具栏参数按钮与默认 `Alt+Shift+E` 使用同一面板开关：关闭时打开并进入编辑；编辑或预览时触发则关闭面板。快捷键可在首页工具栏设置中修改。参数按钮在编辑和预览时均保持选中；工具栏和参数标题栏均不另设关闭按钮。`Esc` 先关闭下拉菜单或数值输入，随后按“编辑 → 预览 → 关闭”逐级退出。编辑时单击游戏区域保留预览；预览时单击参数面板（含标题栏和子区域）直接返回编辑，首击只激活编辑，按下／松开均不触发参数或游戏操作。预览面板以外仍可正常操作游戏。切到其他应用立即取消输入接管，沿用原有窗口／全屏切屏规则。

`Ctrl+单击` 滑条可直接输入参数数值。输入使用实际参数单位，按声明的步长归一化并限制在范围内；普通拖动继续使用离散步数。例如步长为 0.05 时输入 0.73，会应用 0.75。

工具栏悬停提示统一为“按钮名”或“按钮名（当前快捷键）”，不附带操作或状态说明。固定、性能分析、实时参数、对比、截图使用对应绑定；切换模式使用目标模式的快捷键，停用使用当前模式的快捷键。修改或清除绑定时同步更新，最小化与演示窗口没有绑定则只显示名称。

## 实现及自动验证

- 使用 `WS_EX_NOREDIRECTIONBITMAP` 的可激活输入宿主覆盖渲染区域，保持原有 ImGui 绘制。原生原型验证透明像素、整窗命中、激活、解除光标限制、首击完整交接和后续游戏点击。依据：[Microsoft Windows Composition 文档](https://learn.microsoft.com/en-us/archive/msdn-magazine/2014/june/windows-with-c-high-performance-window-layering-using-the-windows-composition-engine)。
- 预览在 ImGui 内保持只读，使用仅覆盖最后成功呈现的面板范围的原生宿主接收激活点击；显示该区域不会获取焦点。点击时激活宿主并扩展至渲染区域，完整接收首击，之后允许编辑。区域随成功呈现更新并裁剪到渲染范围，呈现失败不提前移动命中区域。编辑时使用宿主鼠标捕获维持越界拖动。鼠标、键盘、字符和取消事件经过现有输入队列，无游戏新帧时沿用缓存画面的叠加层刷新。
- 预览时的普通 `Esc` 经现有缩放线程键盘钩子接收，仅在游戏／缩放窗口前台时接管首次按下、重复和松开。松开后由外层循环关闭，不在钩子中修改 ImGui 或焦点；其他应用、系统组合键及已经按住的 Esc 不被接管。状态变化或切出应用会取消待执行关闭。
- 参数宿主被识别为缩放内部窗口。编辑优先于 3D 模式锁鼠，缩放窗口不主动抢回焦点。激活和返回游戏前再次检查当前前台窗口；失败显示“请点击游戏窗口恢复控制”，不循环激活。
- 主动停止、手动／自动参数重建、切换缩放模式，以及源窗口变化导致的重建，都等待参数层接收完尚未松开的输入。停止之后释放捕获、光标限制和宿主。游戏已关闭或用户切到外部应用时立即清理，尊重新焦点。
- 重建保存面板位置、大小及编辑／预览状态，并保留已经请求的返回游戏或关闭状态。窗口移动和 DPI 变化更新宿主范围、面板布局及缩放。
- 原生负例确认：只拦截已经交付按下事件的松开事件，会使 Windows 异步按键状态仍然显示按下。因此不采用“只吞松开”的全局输入钩子。参数快捷键仅在自身吞掉首次按下时接管其重复和松开；已按住的键不接管松开。

执行 `tests/Run-ParameterInputTests.ps1` 可编译并运行提取自生产实现的输入与布局测试。`-NativePrototype` 额外创建两个测试窗口，验证真实 USER32/DWM 行为，结束后恢复原光标和焦点。

自动回归覆盖三态、预览标题／控件／子区域首击恢复编辑、面板外游戏输入、失败呈现命中范围、首击成对交接、滑条拖出边界、下拉区域、数值键盘输入、Esc 逐级退出及长按／组合键／外部焦点保护、快捷键修饰键交接、恢复保护、焦点失败和停止等待输入结束。原生测试验证预览宿主的有界命中、不主动激活以及首击激活后按下／松开不落入游戏。布局回归覆盖位置和大小恢复、折叠、缩小再放大，以及 16 种视口／DPI 组合。
